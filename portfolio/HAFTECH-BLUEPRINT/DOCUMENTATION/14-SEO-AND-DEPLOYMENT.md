**Objective.** Document the domain, email, hosting and search setup needed for a trustworthy launch.

## 14.1 Domain strategy
- **Preferred:** haftech.com, subject to availability and verification via the registrar's WHOIS/availability check.
- **Structure:** one domain, paths for each area: `haftech.com`, `/founder`, `/work`, `/projects` (no separate founder domain at launch).
- **Defensive/secondary:** consider the `www` alias (redirect to apex or vice versa; pick one canonical) and, if available, a country domain; decision `OPEN`.
- **Registrar hygiene:** registrar lock, 2-factor authentication, auto-renew, WHOIS privacy where available, domain registered under an account the founder controls.

## 14.2 DNS and SSL
- Point the apex/`www` to Vercel following Vercel's current DNS instructions; use Vercel-issued certificates (automatic HTTPS, HSTS enabled after verification).
- Keep DNS records documented in the repo (non-secret) and reviewed on change.
- Set a CAA record limiting certificate issuance (optional hardening).

## 14.3 Business email
- Use a hosted mailbox provider (e.g. Google Workspace or Zoho) for `hello@`/`contact@` on the domain; transactional contact-form mail through a separate provider (doc 12).
- Authentication records:
  - **SPF:** one TXT record listing authorised senders, ending in `~all` (or `-all` after testing). Only one SPF record per domain.
  - **DKIM:** publish the provider-supplied selector keys for each sending service (mailbox provider and transactional provider).
  - **DMARC:** start with `v=DMARC1; p=none; rua=mailto:<reports address>` to monitor, then move to `quarantine` and `reject` once reports show alignment.
- Verify with test messages and a header check before launch. Record the exact values in the launch runbook; they depend on the chosen providers (`OPEN`).

## 14.4 Search and discovery
| Item | Specification |
|---|---|
| Search Console | Add a Domain property (DNS verification); submit the sitemap; monitor coverage and Core Web Vitals |
| Analytics | Privacy-friendly tool (doc 12); conversions = contact form submissions |
| Sitemap | Generated by `app/sitemap.ts`, includes all public routes and detail pages with `lastModified` |
| robots.txt | Allow all public pages; disallow preview environments; reference the sitemap |
| Canonical URLs | Self-referencing canonical on every page; single host and protocol |
| Redirects | `www` ↔ apex 308; trailing-slash policy consistent |
| Open Graph / Twitter cards | Title, description, 1200×630 image per page and per project/article; `og:type` article for journal |
| Social previews | Test with platform debuggers before launch |

## 14.7 Launch runbook
1. Confirm domain ownership and registrar security.
2. Configure DNS to Vercel; verify HTTPS and redirects.
3. Configure mailbox and transactional email; set SPF, DKIM, DMARC; send tests.
4. Set environment variables in Vercel (doc 12 §12.15).
5. Run the full checklist (doc 13 §13.6) on the production-candidate preview.
6. Deploy to production; verify sitemap, robots, canonical, OG images.
7. Add Search Console property and submit the sitemap; confirm analytics events.
8. Monitor Core Web Vitals and form delivery for two weeks.

## 14.8 Acceptance criteria
Domain resolves with valid HTTPS; email authentication passes; sitemap and robots correct; structured data validates; social previews render.
